# 排版規則

交付含排版輸出時逐條核。以 [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines) 為基準；本檔是課堂用的九條操作版。半形標點掃描見 [glyph-scan.md](glyph-scan.md)。

1. 中文與英文、阿拉伯數字之間加一個半形空格；數字與單位之間也加空格：使用 GitHub、共 3 台、10 Gbps、20 TB。官方名稱內部格式例外。
2. 百分比與角度符號緊貼數字：提升 15%、角度為 90°。不要對 URL、IP、版本號、日期或識別字內部套用空格規則。
3. 中文句子使用全形標點：，。！？；：、「」『』（）。全形標點旁不額外加空格；此規則優先於中西空格，例如：設定（API）、使用 GitHub，然後登入。全形與半形括號不得混用（`PORT(S）` 是錯的）。
4. 不堆疊驚嘆號或問號。指北允許單組「？！」；一般說明依語氣擇一即可。不要把省略號「……」、破折號「——」或 Markdown 語法當成重複標點刪除。
5. 數字使用半形；僅在使用者要求設計對齊時保留全形數字。
6. 完整英文句子與專有名詞內部保留半形標點；引用英文句子時可外加「」，不把所有英文句子都強制加上引號。中文句子中的英文書名、報刊名用斜體，不用中文書名號。
7. 保留正確大小寫，例如 GitHub、macOS、JavaScript、TypeScript；不要自創難辨識的縮寫。指令中的 `github` 等字串不因此更名。
8. 行內程式碼與中文間留空格，例如：將資料寫入 `config.yaml` 裡。若旁邊是全形標點則不加空格，例如：修改 `config.yaml`，再重新載入。
9. 中文超連結兩側空格屬指北的偏好項目，不是語法錯誤。沿用文件一致風格；英文或數字顯示文字仍依中西空格規則處理。

交付前確認：連結與程式碼仍完整可用；排版規則沒有動到受保護內容。
