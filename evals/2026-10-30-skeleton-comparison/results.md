# 對比結果 2026-10-30（v3.0.0 vs v3.1.0-skeleton）

方法：同一基底模型、單一隔離子代理讀骨架版全文（SKILL.md＋三個 references 內聯），跑 `evals/2026-10-27-v3-comparison/cases.md` 同一組 8 題（期望欄未給）。基準輸出＝`evals/2026-10-27-v3-comparison/results.md` 記錄的 v3.0.0 列（原檔 /tmp/eval_out_new.md）。骨架版輸出在評測時為 /tmp/eval_out_skel.md。

注意：這 8 題已用過一輪，對「新能力」不再 held-out；對本次「重組前後等價與否」的比較仍公平，因兩版面對同一組。下一輪改規則請開新 cases。

## 逐題結果

| # | 考點 | 骨架版 vs v3.0.0 |
|---|---|---|
| 1–7 | 同詞不同義、已自然、大陸用語、公告、聊天、引文、不確定性 | **逐字相同**，全對 |
| 8 | 模板腔段落 | 同方向修正（刪空泛開場、上雲→雲端、賦能→帶動）；措辭不同：v3 寫「公司已全面遷移至雲端…我們應…」，骨架寫「公司全面轉向雲端服務後…我們應該…」。**骨架版更貼原文語氣**（原文用「應當」，v3 降成「應」是輕微過度編修） |

## 額外信號

- 子代理依交件規格報告了開過的 references 與跑過的三個掃描（rg exit code 記錄）、並用「原文 → 修訂」格式列判斷依據。此行為部分是我在 prompt 明示要求的，不算完全自發；但格式與 skill 的交件規格一致，管線接上了。
- 骨架版 SKILL.md 7.4KB（v3.0.0 為 10.5KB，-30%）；本輪 references 全被需要，所以总 token 沒有省。省的場景是簡單任務（短回覆只需 SKILL.md＋glyph-scan）——這是推論，未實測。

## 結論

- 重組沒有回歸：8/8 等價，1 題語氣忠實度略優。
- 本比較只能支持「結構重組安全」，不能支持「骨架結構提升品質」——那需要新 held-out 題與多模型。

## 仍存在的失敗模式（與 v3 相同，未因重組消失）

1. 窄領域新譯名仍需查證，skill 只給流程強調，無法保證執行。
2. 「保留語氣」vs「刪套版」的界線仍是判斷題，案例 8 兩版都判斷正確但措辭不同，說明界線在模型不在規則。
3. 長文一致性、跨模型穩定性仍未測。
